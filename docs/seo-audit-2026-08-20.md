# Max Law SEO Audit

**Audit date:** 2026-08-20  
**Site:** https://www.maxlawnv.com  
**Related strategy:** `docs/seo3.md`

## Scope

- Reviewed local Next app routes, metadata exports, sitemap, robots, structured data, navigation, and priority practice pages.
- Checked the live homepage, practice index, priority practice pages, robots.txt, sitemap.xml, and referenced Open Graph assets.
- Ran production build and lint commands to identify technical blockers.

## Executive Summary

The site already has useful SEO foundations: indexable routes, canonical metadata on most pages, live robots.txt and sitemap.xml, many practice pages, CTAs, and structured data helpers.

The main SEO problem is topical dilution. The agreed business goal is personal injury and car accident lead generation, but the homepage, practice index, global schema, service areas, and navigation repeatedly position the firm as "Personal Injury & Criminal Defense." That matches existing broad rankings, but it weakens the signal for the revenue keywords in the playbook.

The highest-impact next work is:

1. Reposition homepage and `/practice` around Las Vegas personal injury and car accidents.
2. Fix technical blockers: production build, lint script, robots rule blocking `/_next/`, missing OG images, placeholder Google verification metadata.
3. Strengthen priority landing pages with keyword-aligned H1s, visible FAQs, breadcrumb schema, internal links, and safer/legal-review-ready copy.
4. Update sitemap priorities and lastmod behavior so the sitemap reflects the SEO plan.

## Technical SEO Findings

### High Priority

1. **Robots blocks Next assets**
   - File: `src/app/robots.ts`
   - Current rule disallows `/_next/`.
   - Risk: Googlebot may be blocked from rendering CSS/JS assets. Remove `/_next/` from `disallow`.

2. **Production build fails**
   - Command: `npm run build`
   - Result: Turbopack fails while parsing `instrumentation-client.ts` and `instrumentation.ts` with `Operation not permitted (os error 1)` while creating a process/binding a port.
   - Risk: cannot trust deploy readiness or rendered metadata until build is clean.

3. **Lint command is broken for Next 16**
   - Command: `npm run lint`
   - Current script: `next lint`
   - Result: `Invalid project directory provided ... /MaxLaw/lint`
   - Risk: CI/local validation cannot catch SEO and accessibility regressions. Replace with an ESLint command compatible with Next 16.

4. **Referenced Open Graph images return 404**
   - Missing live assets:
     - `https://www.maxlawnv.com/og-car-accidents.jpg`
     - `https://www.maxlawnv.com/og-motorcycle-accidents.jpg`
     - `https://www.maxlawnv.com/og-about.jpg`
     - `https://www.maxlawnv.com/og-media.jpg`
   - Local references found in `src/app/practice/car-accidents/page.tsx`, `src/app/practice/motorcycle-accidents/page.tsx`, `src/app/about/page.tsx`, and `src/app/media/page.tsx`.

5. **Title template causes double branding**
   - Root layout title template appends `| The Law Offices of Saggese & Associates`.
   - Several page titles already include `| Saggese & Associates`, producing long live titles such as:
     - `Las Vegas Wrongful Death Lawyer | Saggese & Associates | The Law Offices of Saggese & Associates`
   - Fix by removing brand suffixes from page-level titles or changing the template.

### Medium Priority

6. **Google verification metadata is a placeholder**
   - File: `src/app/layout.tsx`
   - Current metadata uses `google: 'your-google-verification-code'`.
   - A live verification file exists at `/google672e3108f67e1467.html`. Either remove the placeholder metadata or replace it with the real token if needed.

7. **Sitemap uses runtime `new Date()` for all lastmod values**
   - File: `src/app/sitemap.ts`
   - Live sitemap shows identical lastmod timestamps across all URLs.
   - Risk: lastmod does not reflect real content updates. Use stable file mtime, explicit dates, or omit lastmod until reliable.

8. **Sitemap priorities do not match the SEO strategy**
   - `/practice` and `/contact` are 0.9.
   - All practice and criminal-defense detail pages are 0.7.
   - Recommended: Home 1.0; Personal Injury hub and Car Accident 0.9; Motorcycle, Truck, Wrongful Death 0.8; long-tail injury 0.7; criminal-defense lower unless the client wants to keep pursuing those rankings.

9. **Thin utility routes are routable**
   - `/plain` and `/plain-danger` are simple diagnostic pages and are not in the sitemap.
   - Add `noindex` metadata or remove/guard them from production.

## Schema Findings

### What Exists

- Homepage emits LegalService, Person, and Organization JSON-LD.
- Practice pages use `PracticeStructuredData`.
- Car and motorcycle pages also emit separate LegalService schema from their client components.
- Breadcrumb JSON-LD exists via `Breadcrumbs`, but only pages using that component get it.

### Gaps

- Global LegalService/Organization schema still describes both personal injury and criminal defense, which conflicts with the current PI-first SEO plan.
- Breadcrumb schema is not consistently emitted across priority practice pages.
- FAQ schema is sometimes present without a visible matching FAQ section on the page. FAQ content should be visible to users.
- Car accident page lacks FAQ schema/visible FAQ even though the playbook requires FAQ sections on important pages.
- `PracticeStructuredData` combines `LegalService` and `FAQPage` in one `@type` array. Prefer separate, explicit LegalService and FAQPage nodes for cleaner validation.

## Content Findings

- Homepage H1 is brand-first, not keyword-first. This is acceptable for brand, but the supporting text should more clearly reinforce "Las Vegas personal injury lawyer" and "car accident lawyer."
- `/practice` is not a true personal injury landing page. It is a mixed directory and gives criminal defense equal topical weight.
- Priority practice page H1s are generic:
  - `Car Accidents`
  - `Motorcycle Accidents`
  - `Truck Accidents`
  - `Wrongful Death`
  - Recommended H1 style: `Las Vegas Car Accident Lawyer`, etc.
- Several pages use statistics or outcome-style statements without visible sourcing. Examples include wrongful death limitations/settlement claims and truck accident statistics. These should be sourced, softened, or removed after legal review.
- Internal linking exists, but the homepage and practice index should create a stronger injury silo:
  - Home -> Personal Injury hub -> Car Accidents -> supporting long-tail pages.
  - Car Accidents -> uninsured/underinsured, distracted driving, pedestrian, commercial vehicle, motorcycle, truck, medical treatment content.
